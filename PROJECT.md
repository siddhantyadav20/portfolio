# Siddhant Yadav — Portfolio

## Purpose

This is the personal portfolio of Siddhant Yadav, a Product Designer
with approximately 5 years of experience.

The primary goal is to help me get hired for Product Design,
UX/Product Design and Design Engineering roles.

The website should demonstrate my ability to:

- think deeply about products
- simplify complex workflows
- design sophisticated interactions
- create strong visual systems
- work closely with engineering
- move between design and implementation

## Core Idea

The website itself is a product experience.

It should not feel like a conventional portfolio consisting of:

Home → Work → About → Contact.

Instead, the homepage is an interactive workspace containing
different entry points into my work, thinking and personality.

A visitor should understand who I am and what I do without interacting
with anything, while interaction progressively reveals more depth.

## Experience Philosophy

The site should feel:

- premium
- minimal
- tactile
- editorial
- intelligent
- playful in small, intentional moments
- highly crafted

It should NOT feel:

- like a portfolio template
- like an Awwwards experiment although it should make the cut
- overloaded with animation
- like an AI-generated website
- like a developer demo
- difficult to understand

## Hiring Principle

The website is ultimately a hiring tool.

A recruiter should quickly understand:

1. Who I am
2. What kind of designer I am
3. What I have actually shipped
4. Why my work is interesting
5. How I think

Interactive elements should support this goal rather than hide the
work behind novelty.

## Content Philosophy

Case studies should not be giant conventional UX documents.

They should primarily communicate individual product decisions,
evolution and outcomes.

Examples include:

- evolving the camera workflow
- search-first information architecture
- AI-assisted remark writing
- design-system scalability
- offline inspection workflows

Individual stories may have different structures depending on what
makes the project interesting.

Never invent professional claims, metrics, research findings,
outcomes, testimonials or other portfolio facts.

## Design Philosophy

Figma is the visual source of truth.

The implementation should reproduce the intent and visual quality
of the Figma design rather than mechanically reproducing every
Figma layer.

Code may simplify implementation where appropriate.

For example:

- repeated decorative lines can be generated programmatically
- repeated visual patterns can be implemented with CSS
- Figma-specific layer structure does not need to become React
  structure

## Interaction Philosophy

Interactions should feel like natural extensions of the concept.

Examples:

- Inspection → prototype/video
- Search → actually search
- Design System → scaling
- Designer/Engineer → transition
- Workspace → exploration
- Timeline → time exploration

Avoid adding interactions simply because they are technically possible.

## Technical Philosophy

Prefer the smallest architecture capable of expressing the experience.

Avoid unnecessary:

- databases
- CMSs
- global state libraries
- animation libraries
- 3D/WebGL
- external services

unless a real requirement emerges.

Performance, accessibility and responsiveness are part of the design,
not post-launch cleanup.

## Current State

The Figma file is actively being developed.

Some case-study content, prototype videos and other assets are not
finished yet.

This must NOT block implementation.

Use clearly identifiable placeholders where required and make
unfinished content replaceable without restructuring the application.
